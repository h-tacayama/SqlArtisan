# 危険の型の一覧（案）

この試しの手法（型の模型 × 全レーンの実測）を広げる単位として、SqlArtisan の危険の型を一覧に
した。依頼者と合意したものではない。

根拠にした記録:

- 文書の `[!WARNING]`（静かな誤りとして記録したもの）: README・`docs/`・`docs/guides/` の 20 か所
- CHANGELOG の Fixed: 192 項目
- guards の分類（ADR 0007・0011・0012・0017）
- 解析器の規則（SQLA0001〜0303）
- 試しで見つけたもの

「手法が合う」は、エンジンごとに読み方が分かれ、全レーンの実測で静かな誤りが見える型を指す。
エンジンが関わらない型（ライブラリの状態や C# の解決）には、別のやり方が合う。

## 0. 結果（先に）

- **型は 20 個。** 手法が合うものが 12、一部だけ合うものが 3、合わないものが 5。
- **済んだのは 2 つ**（H1 値の読み取り、H2 名前の解決）。族 4・11 は H4 の一部を測っている。
- **残りの合う 10 型と、一部だけ合う 3 型にかかる見込み: 私の作業時間で約 18〜31 時間。**
  - 一部だけ合う 3 型を除けば、約 14〜24 時間。
  - 依頼者の判断の時間と、決めたことをコードに入れる時間は含まない。
- **優先の推奨**（静かな誤りの記録の多さと、今あるゲートの薄さから）:
  1. H3 文字列の位置
  2. H4 関数の意味
  3. H5 日時
  4. H10 DML の意味
  5. H6 NULL

## 2. 見込みの合計

| 範囲 | 型 | 時間 |
|---|---|---|
| 手法が合う残り 10 型（H3〜H12） | 10 | 約 14〜24 時間 |
| 一部だけ合う 3 型（H13〜H15） | 3 | 約 4〜7 時間 |
| 計 | 13 | **約 18〜31 時間** |

見込みに入っていないもの:

- 依頼者の判断の時間。1 型あたり 2〜4 回のやり取りだった。問いのセルが多い型では増える。
- 決めたことをコードに入れる時間。この試しでは一つも入れていないので、わからない。
- 型どうしの重なり。H6・H7 は H1 と、H8 は H2 と重なる。重なる分は短くなる見込みだが、どれだけ
  短くなるかは測っていない。

## 3. 優先の推奨と理由

| 順 | 型 | 理由 |
|---|---|---|
| 1 | H3 文字列の位置 | 静かな誤りの記録が多い（`[!WARNING]` 3 件、Fixed の #679・#706・#719）。位置の一覧（ADR 0016）があり、生成器を作りやすい。既存のゲートは位置の一覧を確かめるが、エンジンでの読み方を全レーンでは見ていない |
| 2 | H4 関数の意味 | `[!WARNING]` が一番多い（8 件）。族 11 で 41 件の食い違いが出た。`MatrixSweepTests` は「動くか」だけで値を見ないので、穴が大きい |
| 3 | H5 日時 | F3・F5 が出た。日時部分のセルはゲートがあるが、算術と型は記録が薄い |
| 4 | H10 DML の意味 | F4 と MySQL の 1093 が出た。書き込みは間違うと行が壊れる |
| 5 | H6 NULL | H1 の基盤をそのまま使える。`Sql.Null` との比較（#759）は、全エンジンが同じ結果なので照合では見えなかった型で、意図の基準を先に決める必要がある |

## 4. この一覧で確かめていないこと

- 一覧が漏れなく揃っているかはわからない。記録（`[!WARNING]`・Fixed・guards・解析器）から作った
  ので、記録のない種類の型は入っていない。
- 「手法が合うか」と時間の見込みは判断で、どの型でも試していない（H1・H2 を除く）。
- CHANGELOG の Fixed 192 項目は、型ごとに数えていない。例として挙げただけ。
- H4 の量（約 230 の構文）は DialectMatrix の数で、関数ごとの引数の組み合わせまでは数えていない。
